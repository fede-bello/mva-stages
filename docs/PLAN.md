## Decisions taken from the research (and where they adapt the brief)

| Topic | Decision | Why |
|---|---|---|
| Router | React Router 8 **data mode** (`createBrowserRouter`, `RouterProvider` from `react-router/dom`), no loaders | `<ScrollRestoration>` is not available in declarative mode; `react-router-dom` no longer exists in v8. Product unchanged |
| Lint | Oxlint, as the current Vite template ships (`npm run lint`) | The template no longer ships ESLint |
| Fonts | IBM Plex Sans 400/500/600/700 and Plex Mono 400/500, **self-hosted with Fontsource**, latin subset | Same fonts as the design, no third-party request, better Lighthouse |
| Key | Publishable key `sb_publishable_...` as `VITE_SUPABASE_PUBLISHABLE_KEY` | Recommended by Supabase; legacy anon keys deprecated end of 2026 |
| Supabase project | Created through the **Vercel Marketplace integration** (`vercel integration add supabase`, region `cdg1` = `eu-west-3`) in the Vercel-managed org `fede-bello's projects` | Supabase docs: projects in a Vercel-managed org can only be created from Vercel. The DB password is generated by the integration (strong, random) and kept only in `.env.local` |
| Custom events | `track()` is implemented (3 events, at most 2 non-personal properties each) but **the account is on Vercel Hobby, where custom events are not collected** ("Custom Events are available on Enterprise and Pro plans", vercel.com/docs/analytics/custom-events, read 2026-11-09). Page views work. No upgrade | Paid plan change is not ours to make |
| Verified | "Verified only" keeps its strict meaning (`verified = true`). Today no offer is verified, so the empty state for that case says so. Badge `Unverified · added by a student` only when `source_type = 'user_submitted' && !verified` | All 668 swept offers are unverified by the data rule; showing "added by a student" on them would be false |
| Dimmed cards | Closed and removed cards are dimmed **without** `opacity: 0.62` (fails AA): paper background, no white, title in ink-2, neutral pill | Keeps "atenuadas" and passes AA |
| Contrast fixes | Input/chip/outline borders `#858178`; focus ring inside the dark header `#A9BBFF` | 1.71:1 and 2.38:1 in the design fail WCAG 1.4.11 |
| Effective status | `open` with `deadline < today` (Paris date) is shown, counted and filtered as `closed`. Not written back | CLAUDE.md: closed when the deadline passed |
| Rendering | All rows fetched once; first 50 cards rendered, then `Show more offers ({n} left)` in steps of 50; reset on filter change; `content-visibility: auto` on cards | 580+ cards would hurt mobile performance |
| Topic chips | Every topic present in the data, sorted by count desc, `other` last | The design's 12 omit physics-sim (80), robotics (48)... |
| Countries | Atomic countries split from `country` (on `,` and ` or `, parentheses stripped, `USA` → `United States` in the UI), sorted by count, label `France (439)` | Real values are messy |
| Contact | New table `contact_requests` + form in `/legal#contact`; optional reply email stored privately, said on the page | Brief: contact is not an email |
| Personal emails | Client check on submit **and** DB guard in the public-insert trigger (new migration) | Public inserts bypass `build_seed.py` |
| Submit "Where you found it" | Stored as the first line of `notes` (`Found on: LinkedIn.`); link optional for MVA Drive and Mailing list; Drive/Docs links rejected | `source_type` is forced by the trigger; no Drive links rule |
| Submit reference | Optional `Reference` field added | Duplicate check by reference needs it |

security boundary. No server code.

## Frontend data model

- Types: `Tables<'offers'>` from `database.types.ts`. One query:
  `supabase.from('offers').select('*', { count: 'exact' })`; if `count > data.length` show a console
  warning (1000-row cap) and fetch the rest with `.range()`. Report counts:
  `from('offer_report_counts').select('*')`, used on the offer page only.
- `today` = current calendar date in Europe/Paris, as a UTC midnight timestamp.
  `daysUntil(deadline) = round((Date.UTC(deadline) - today) / 86400000)`.
- Effective status: `status === 'open' && deadline && daysUntil < 0` → `closed`, else `status`.
- Soon: effective `open`, deadline set, `0 <= days <= 21`. Pill text `Closes today` / `Closes in 1 day` /
  `Closes in N days` in the warn style; else `Open`, `Expected, not published yet`, `Closed`,
  `Posting removed`, `Status unknown` (design labels).
- Stats over all offers (effective status): Open = count effective `open`; Closing in 3 weeks = soon;
  Stipend stated = `stipend_min_eur_month != null`; Last sweep = `max(status_checked)` as `DD Mon`
  (year added if not current year).
- Filters (`filters.ts`), query keys: `q`, `topics` (comma list), `country`, `open=0` (default on),
  `april=1`, `paid=1`, `verified=1`, `sort` (`deadline` default, `stipend`, `az`). Writes use
  `{ replace: true, preventScrollReset: true }`. Search debounced 250 ms, accent and case folded,
  over organization, title, title_en, city, country. Topics OR. Country = atomic match.
- Sort: deadline = status rank (open 0, expected 1, unknown 2, closed 3, removed 4) then days
  (null = 9999) then organization; stipend = `max ?? min ?? -1` desc then deadline; A to Z =
  organization (`localeCompare`, `en`, sensitivity base) then title.
- Card derivations and label maps: exactly `docs/research/design.md` 5.4 and 5.5 (place string,
  "via" source label, duration, start, stipend text, deadline `Rolling or not stated`).
- Similar offers: other offers with effective `open`/`expected`, scored by shared topics ignoring
  `other`, at least 1, ties by soonest deadline (nulls last), max 3, section hidden if none.
